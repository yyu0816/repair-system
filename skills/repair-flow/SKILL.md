# Skill: 處理報修狀態切換與負責人指派驗證

## 1. 輸入
* 目標案件 ID (`id`)
* 目標處理狀態 (`status`)：必須為五階段之一（待審核、處理中、等待零件、已完結、已取消）
* 維修負責人 (`assignee`)：文字字串或空值

## 2. 處理步驟
1. **接收 PATCH 請求**：讀取前端傳入的 `status` 與 `assignee` 資料至 `app.py` 的 `/api/tickets/<id>` 端點。
2. **狀態與負責人連動檢查**：
   * 檢查 `status` 是否合法。
   * **規則檢查**：若 `status` **不等於**「待審核」，則 `assignee` 欄位**絕對不能為空**。
3. **回傳結果**：
   * 若檢查失敗，攔截並回傳錯誤訊息（HTTP 400）。
   * 若檢查通過，更新記憶體中的案件資料，並回傳更新後的案件狀態與負責人資訊。

## 3. 檢查與輸出
* [ ] 非待審核狀態下缺少年維修負責人時，是否成功被系統攔截並拒絕儲存？
* [ ] 待審核狀態是否允許清空維修負責人？
* [ ] 儲存後後台表格是否能正確重新整理並顯示最新狀態與負責人？
